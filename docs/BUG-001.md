# BUG-001 — Total do carrinho ignora quantidade

> **Case study de QA e debugging em ambiente simulado (ShieldMart / Code Shield).** Os defeitos foram introduzidos intencionalmente para treinamento. Não se trata de auditoria de um cliente nem de transações reais.

## Comportamento e reprodução

1. Partindo de um carrinho vazio, adicionar **Teclado Mecânico**, de preço unitário **R$ 150,00**.
2. Aumentar a quantidade para **2**.
3. Verificar o total calculado.

**Esperado:** R$ 300,00 (`150 × 2`).

**Observado antes da correção:** R$ 150,00. O cálculo considerava o preço unitário uma única vez, independentemente da quantidade.

O problema também era reproduzido com produtos diferentes: **2 teclados (R$ 150,00 cada) + 1 mouse (R$ 90,00)** deveriam somar **R$ 390,00**, mas a implementação retornava **R$ 240,00**.

## Investigação e causa raiz

A função `calculateTotal()` percorria os itens com `Array.reduce()`, somando **apenas** `item.product.price`:

```ts
return items.reduce((total, item) => total + item.product.price, 0);
```

O campo `item.quantity` não era utilizado. Isso explica por que o cenário com **uma** unidade passava, enquanto os cenários com quantidades maiores falhavam.

**Causa raiz:** ausência da multiplicação entre preço unitário e quantidade na agregação do total.

## Correção

Expressão corrigida, presente em [`src/domain/cart.ts`](../src/domain/cart.ts):

```ts
return items.reduce(
  (total, item) => total + item.product.price * item.quantity,
  0
);
```

Agora cada item contribui com `preço × quantidade` para o acumulador.

**Observação sobre rastreabilidade:** o primeiro commit publicado no GitHub (`51736fc`) **já continha essa correção**. Por isso, esta PR documenta retrospectivamente a investigação e **não** apresenta uma alteração de lógica de `calculateTotal()` em seu diff. O registro da falha original é a saída de teste e a gravação local, não um commit anterior disponível no remoto.

## Aprendizados

- Um teste passando com `quantity = 1` não garante que a regra de negócio esteja correta para outras quantidades.
- Testes que variam entradas ajudam a identificar omissões na lógica.
- Uma documentação técnica útil registra **sintoma → teste que falhou → causa raiz → correção → reteste**, distinguindo evidências reais de verificações ainda pendentes.
